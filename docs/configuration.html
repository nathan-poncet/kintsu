Configuration

One file. Every knob.

~/.config/kintsu/config.toml, written by kintsu setup, checked by kintsu doctor, overridden per project by a .kintsu.toml at the root of a repository. This page is the designed schema; it may still move until v0.1 ships, and every change will be listed in the changelog.

Models

A model is a named endpoint: a provider, a model id, how to reach it, what it may be used for. Name them the way you will read them in kintsu models: tiny, haiku, local-big, work.

[models.<name>]
[models.tiny]
provider = "ollama"                    # ollama · openai_compatible · anthropic · gemini · cli_agent
model    = "qwen3:1.7b"
tier     = "tiny"                      # tiny · small · large · agent
base_url = "http://127.0.0.1:11434"    # optional, this is the default for ollama
timeout  = "8s"

[models.haiku]
provider = "anthropic"
model    = "claude-haiku-4-5-20251001"
tier     = "small"
key      = { keychain = true }         # or { env = "ANTHROPIC_API_KEY" } · { command = "op read op://dev/anthropic/key" }
max_output_tokens = 800

[models.router-big]
provider = "openai_compatible"
base_url = "https://openrouter.ai/api/v1"
model    = "anthropic/claude-sonnet-5"
tier     = "large"
key      = { env = "OPENROUTER_API_KEY" }

[models.claude-code]
provider = "cli_agent"
command  = "claude"                    # a preset: claude · codex · opencode · aider · gemini · copilot
tier     = "agent"
providercoversneedswhere
ollamaany model Ollama serves; health and listing through the native APIOllama runninglocal
openai_compatibleOpenAI, OpenRouter, Groq, Mistral, Together, LM Studio, llama-server, vLLM, anything with /v1/chat/completionsbase_url, a key unless localcloud or local
anthropicthe Messages API, streaming, structured output through toolsa keycloud
geminithe Gemini APIa keycloud
cli_agentClaude Code, Codex, OpenCode, aider, Gemini CLI, Copilot CLI, or any command templatethe CLI installed and logged inyour account

Tiers are what the router reasons about. tiny: up to about 2B parameters, answers in a few hundred milliseconds, always local. small: 7 to 14B local, or a Haiku-class API. large: a frontier model. agent: a CLI with tools, not a chat completion.

Routing

Five tasks. For each, an ordered list of model names. The router takes the first candidate the constraints allow and whose circuit is closed; on a timeout or an error it moves to the next. rules-only is a pseudo-model meaning "do without a model" and every list ends with it whether you write it or not.

[routing]
[routing]
classify    = ["tiny", "rules-only"]
quick_fix   = ["tiny", "haiku"]
explain     = ["haiku", "tiny"]
investigate = ["claude-code", "router-big"]
summarize   = ["tiny", "haiku"]

[routing.budgets]                    # latency budgets; a candidate that cannot meet one is skipped
classify  = "300ms"
quick_fix = "3s"
explain   = "1s"                     # to the first token; explanations stream
summarize = "2s"
taskinputoutputtypical tierwhen
classifycommand, status, the first lines of outputcategory, worth-a-bubble, confidencetinyafter every offer, asynchronously, to enrich or retract the toast
quick_fixthe caseone command, confidence, dangersmallwhen no rule knew; on Fix, or eagerly if eager_fix = true
explainthe casestreamed prosesmall or largeon Why
investigatethe hand-off briefwhatever the agent doesagenton Agent
summarizelong captured outputa short paragraphtiny or smallbefore sending 400 lines to anyone

classify and quick_fix ask for structured output, a JSON object with command, confidence, danger and rationale, so the bubble never parses prose. explain streams. investigate makes no model call from Kintsu at all when an agent is configured: Kintsu writes the brief and launches the agent.

Constraints

Constraints filter the candidate lists before the router looks at them. They are how a case with a secret in it never reaches a cloud model, and how a budget stays a budget.

[routing.constraints]
[routing.constraints]
sensitive_output = "local_only"       # redaction found a secret in the command or the output
offline          = "local_only"       # no network: nothing is even attempted
private_paths    = ["~/work/acme/**", "~/secrets/**"]   # cases from these directories are local only
max_daily_cost   = "1.00 USD"         # past it, paid candidates are skipped until midnight
max_case_lines   = 400                 # longer output is summarized first, or truncated
constraintvalueeffect
sensitive_output"local_only" · "ask" · "allow"default local_only. ask shows the Privacy tab before any cloud call.
offline"local_only"the only sensible value; here so you can see it.
private_pathsglobsa case whose cwd matches is treated as sensitive.
max_daily_costan amounttracked from the providers' token counts and the prices in kintsu models.
max_case_linesan integerthe summarize task runs first when exceeded.

Keys

A key source, per model, in order of preference. The daemon reads keys once, keeps them in memory, never logs them, never puts them in the protocol.

key = { … }
key = { keychain = true }                                  # macOS Keychain or Linux secret-service; stored by `kintsu login haiku`
key = { env = "ANTHROPIC_API_KEY" }                       # read from the daemon's environment
key = { command = "op read op://dev/anthropic/key" }      # run once, output trimmed
key = { literal = "sk-ant-…" }                            # works; kintsu doctor warns about it

A cli_agent has no key: the CLI brings its own login. That is how a Claude, ChatGPT or Copilot subscription is reused without an API key.

Agents

Presets know how to hand a brief to the popular CLIs. A template covers anything else. {brief} is the path of the Markdown brief Kintsu wrote; {brief_text} inlines it.

[models.<agent>]
[models.claude-code]
provider = "cli_agent"
command  = "claude"                              # preset: claude "$(cat {brief})"
open_in  = "pane"                                # pane · split (tmux, Herdr) · print (streamed into the panel)

[models.my-agent]
provider = "cli_agent"
template = "myagent --task-file {brief} --yes-i-am-sure=false"
open_in  = "split"
presetruns
claudeclaude "$(cat {brief})", or claude -p when open_in = "print"
codexcodex "$(cat {brief})", or codex exec for print
opencodeopencode run "$(cat {brief})"
aideraider --message-file {brief}
geminigemini -p "$(cat {brief})"
copilotgh copilot suggest -t shell "$(cat {brief})"

The brief is always redacted, always fences the captured output as data, and always ends with the same line: do not run destructive commands without asking. What the user typed after kintsu agent, if anything, goes in as their words.

The bubble

[ui]
[ui]
mode          = "toast"       # toast · hint (one dim line, no links) · panel (always expand) · silent (hotkey only)
hotkey        = "ctrl-k"
accent        = "auto"        # auto (gold, shade by background) · "#d9a441" · "yellow"
style         = "plain"       # plain · boxed
ascii         = false         # true swaps ▎ ⏎ → … for | Enter -> ...
hints         = "first-three" # first-three · verbose · none
language      = "auto"        # from the locale; "fr", "en", …
ghost_text    = true          # zsh and fish
eager_fix     = false         # ask quick_fix on every offer, not only on Fix
screen_reader = false
learning_notes = true         # "Fixed. Next time gti will be corrected without asking."
panel_height  = "auto"        # 6 to 14 lines

Noise

[quiet]
[quiet]
never_triage     = ["vim", "nvim", "less", "man", "ssh", "top", "htop", "watch", "tmux", "fzf"]
ok_statuses      = [130, 141, 148]    # Ctrl-C, broken pipe, Ctrl-Z; add your own
ok_commands      = { grep = [1], diff = [1], test = [1] }   # exit codes that are not failures for a command
same_failure     = "once"             # once · always
dismiss_cooldown = "10m"
coalesce         = "10s"              # at most one async message per case per window while collapsed
off_in           = ["~/scratch/**"]    # directories where Kintsu never speaks
learn_rules      = true               # an accepted model fix, twice, becomes a rule

At the prompt: kintsu ignore with --command, --dir, --session or --always; kintsu mute 1h; KINTSU_DISABLE=1 for a shell you want left alone.

Daemon and hooks

[daemon]
[daemon]
sync_budget = "40ms"      # how long the hook waits for a rule verdict before the toast becomes a message
idle_exit   = "never"     # or "2h": leave after two idle hours; the next failure restarts it
socket      = "auto"      # $XDG_RUNTIME_DIR/kintsu/daemon.sock, else a per-user temp dir
state_dir   = "auto"      # ~/.local/state/kintsu
log_level   = "warn"

[capture]
sources    = ["tmux", "herdr", "wezterm", "kitty", "iterm2"]   # tried in order; only what is present
stderr_tee = false        # zsh only: capture stderr when no source above is available. Opt in.
max_lines  = 400

kintsu service install writes a LaunchAgent on macOS and a user unit on Linux so the daemon survives logout and restarts on a crash. Without it, the first failure of the day starts the daemon and that is fine too.

Per project

A .kintsu.toml at the root of a repository overrides the user file for cases whose cwd is inside it. Anything can be overridden; these are the ones that make sense to commit.

.kintsu.toml
[project]
name    = "acme"
hints   = ["CLAUDE.md", "docs/RUNBOOK.md"]      # files added to the hand-off brief
runbooks = ".kintsu/runbooks/"               # "port 5432 in use" gets the team's answer, not the internet's

[quiet]
never_triage = ["make watch"]
ok_commands  = { "npm run lint" = [1] }

[routing.constraints]
sensitive_output = "local_only"                 # a team can tighten, never loosen, the user's constraints

Commands that touch the configuration

kintsu setupthree questions, writes the file, offers service install
kintsu doctorparses the file, probes every model, prints what works, what is missing and what an answer would cost
kintsu modelsthe table: name, provider, tier, where, health, latency, today's cost
kintsu models test [name]sends a tiny prompt and shows the round trip
kintsu login <name>stores a key in the keychain for that model
kintsu default-configprints the commented default file
kintsu config pathwhich files are in effect for the current directory
