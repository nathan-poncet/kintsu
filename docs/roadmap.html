Milestones

Each version is a list of work items; the bar is how many are done. One hue: gold is shipped, the track is what remains.

Chapters becoming real

The tour on the home page has nine chapters. This is the version in which each one stops being a scripted scene. A second mark means the chapter gets better later.

How the pieces depend

The daemon comes first because everything that remembers, waits or arrives later needs it. Capture comes before Privacy because you cannot redact what you have not read. Routing comes last because it only matters once there is more than one brain.

Version by version

now The skeleton

  • Hooks for zsh, bash and fish, validated in real sessions
  • kintsu triage: quiet on success, Ctrl-C, broken pipes, Ctrl-Z
  • One crate, three rings, the dependency-rule test
  • Design: vision, architecture, daemon, models, the bubble
  • CI on Linux and macOS
  • This website

v0.1 The bubble

  • The daemon: Unix socket, NDJSON protocol, on-demand start, service install
  • Sessions: the last commands, the terminal identity, the last case
  • The rule engine: typos against PATH, cd into a file, git did-you-mean, Docker down, port in use, missing sudo flagged
  • The toast and ghost text in zsh and fish
  • The panel: ^K, five sections, keys, Esc
  • One provider layer: OpenAI-compatible, Anthropic, Ollama; keys from env or config
  • Why, streamed
  • Agent hand-off by preset and template
  • Config file, setup, doctor, default-config
  • Noise control: ignore scopes, mute, dedupe, cooldown, never-triage list

v0.2 It reads the output

  • Output capture: tmux, Herdr, WezTerm, Kitty, iTerm2, OSC 133 marks; the opt-in stderr tee
  • Redaction on by default; the Privacy tab with the exact payload
  • Model fixes with confidence; the danger guard
  • Messages that arrive above the prompt in zsh and fish
  • Clickable words: OSC 8 links and the kintsu:// handler
  • The sentence of the toast from a tiny model; summarize
  • Project awareness: manifests, .kintsu.toml, CLAUDE.md
  • $pipestatus

v0.3 Your agent, your keys

  • Keychain and secret-service; kintsu login
  • Subscription reuse through the CLIs; print mode in the panel
  • Local models first class: Ollama, LM Studio, llama.cpp, MLX
  • Routing per task with constraints, budgets, circuit breakers
  • The cost ledger; kintsu models
  • The MCP server: last_failure, recent_history, captured_output

later Ideas, in no order

  • Learned rules from accepted fixes
  • Team runbooks in the repository
  • CI mode: kintsu wrap -- make test
  • Slow-command hints
  • PowerShell, nushell, elvish
  • Explanations in the user's language, French first
  • Interactive bubble in multiplexer popups
  • A Herdr plugin packaging
  • Homebrew tap, cargo-binstall, prebuilt binaries, Nix, AUR

Not planned

  • A terminal emulator, a shell, a PTY wrapper. Kintsu is a hook and a daemon.
  • A general chat TUI. If you want to chat, Kintsu hands you to one.
  • Autocomplete. zsh-autosuggestions, Amazon Q and inshellisense do that.
  • Running anything on its own. Not now, not as an option, not later.
  • An account, telemetry, a server of ours.

Follow the repository for releases; the changelog is where a version's list becomes fact.
