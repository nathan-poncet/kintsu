Roadmap

Design first. Then the bubble.

No dates. A version ships when its goals work.

  1. now

    The skeleton

    • Hooks for zsh, bash and fish
    • The design, written: architecture, daemon, models, the bubble
    • The installer and this site
  2. v0.1

    The bubble

    The next failure gets a bubble.

    • The resident daemon
    • Rules: typos, wrong directory, git, Docker, ports
    • Why, from one provider layer
    • Hand-off to your CLI agent
    • Ignore, mute, quiet by default
  3. v0.2

    It reads the output

    It knows what went wrong, and shows what it sends.

    • Output capture: tmux, Herdr, the terminals' own APIs
    • Redaction, and the Privacy tab
    • Model fixes with a danger guard
    • Messages that arrive later, clickable words
  4. v0.3

    Your agent, your keys

    Any brain, on your terms.

    • Keychain, and your existing subscriptions
    • Local models first class
    • Routing with constraints and budgets
    • An MCP server for any agent
  5. later

    Ideas

    Learned rules, team runbooks, a CI mode, more shells, more languages, a Herdr plugin.
