The command failed.
Kintsu picks it up.

A small bubble under the error. It fixes the typo, explains the stack trace, or hands the whole case to the AI agent you already use. In your terminal, your shell, with your models and your keys.

Kintsu in forty seconds

The scene plays itself and loops. Take the wheel any time: click a word in the bubble, or focus the terminal and press Tab, ^K, w, f, a, i, p, Esc, ⏎. Nothing here runs a command, and nothing will in the real thing either.

These are scripted scenes of the designed behaviour; Kintsu is pre-alpha. Real recordings replace them the day v0.1 runs.

Seven ordinary failures

What Kintsu actually does with each.

Not features. Situations, the way they happen at 4 pm on a Tuesday, and the exact bubble you would get. Every scene is a small player: it starts when it scrolls into view, and you can click inside it.

You typed it wrong Port already in use Docker isn't running The push was rejected A wall of test output A token in the command Nothing happened, on purpose

01 · Rules, no model

You typed it wrong.

gti status. cd api when the folder is apps/api. The cheapest failures are the most frequent, and they never deserve a round trip to a model.

Kintsu saw
Exit 127, or not a directory. A rule matched the command against your PATH and the directory tree, in under a millisecond.
Kintsu offered
The corrected line, already on your next prompt as ghost text. Tab accepts it; anything else ignores it.
Never happened
No model call. Nothing left the machine. Nothing ran until you pressed Enter.

02 · A read-only probe, a red flag

Port 3000 is already in use.

You start the dev server. EADDRINUSE. Somewhere, a forgotten process from another project still holds the port.

Kintsu saw
The address-in-use error in the output. When you asked Why, the rule ran its read-only probe, lsof -i :3000, and found who.
Kintsu offered
kill 4821, flagged in red because it ends a process. Inserted in your line, not executed.
Never happened
Kintsu killed nothing. You did, with Enter, knowing what it was and where it came from.

03 · A message that arrives later

Docker isn't running.

Cannot connect to the Docker daemon. The error never says the obvious thing: Docker Desktop is closed.

Kintsu saw
The socket error. A rule knows this one and knows the platform: open -a Docker on macOS, systemctl start docker on Linux, sudo flagged.
Kintsu offered
Start it, with Tab. Then, twenty seconds later, a message above your prompt: Docker is up, run the compose again?
Never happened
No polling loop in your shell. The resident daemon watched, and your prompt never waited.

04 · The dangerous option exists, and comes last

The push was rejected.

Non-fast-forward. git's own advice is right there, buried in eight lines of hint:. Someone pushed while you were working.

Kintsu saw
The rejection, and from git log origin/main, who pushed what and when.
Kintsu offered
git pull --rebase && git push. The explanation names the two commits you are missing.
Never happened
git push --force was mentioned, in red, as the thing that would erase their work. Kintsu never proposes it first.

05 · Your agent, briefed

Forty lines of test output.

Three failures. You would scroll, squint, spot the common line, open the fixture, fix the date. Or you would hand it over with everything already attached.

Kintsu saw
Forty-eight lines. A tiny local model found the one panic site shared by the three failures.
Kintsu offered
A one-sentence diagnosis and a hand-off to Claude Code with the brief: command, output, cwd, branch, recent commands, your CLAUDE.md.
Never happened
Kintsu sent nothing to a cloud model. The agent ran in your terminal, on your account, and asked before committing.

06 · Local only, automatically

There's a token in that command.

A curl with a bearer token, a 401. The most useful context for a model is also the one thing that must not leave the machine.

Kintsu saw
Redaction matched Bearer sk-live-… in the command line. The case was marked sensitive.
Kintsu offered
The explanation and the fix, from the local model only. The Privacy tab shows the redacted payload and the routing decision.
Never happened
The token left the machine. Not to a cloud model, not to an agent, not in a log.

07 · Silence is a feature

Nothing happened. On purpose.

Most commands succeed. Some you stop yourself. Some fail the same way twice while you fix them. A tool that speaks every time is a tool you uninstall by Friday.

Kintsu saw
Exit 0, Ctrl-C, a broken pipe from | head, an editor, and the same failure twice in a row.
Kintsu offered
One bubble, for the one real failure. Then kintsu ignore per command, directory or forever, and kintsu mute 1h.
Never happened
A bubble you did not want.

Behind the scenes

Several brains, one per task.

In the scenes above, four different things answered you. A rule. A tiny local model that reads output and decides whether it is worth a bubble. A small model that writes one line. Your agent. Which one does what is a config file, and it degrades gracefully when a brain is missing.

Rules

Instant

Typos, wrong directory, missing flag, Docker down, non-fast-forward push. Ported from the best of thefuck. No model, no network, under a millisecond.

Tiny · local

Classify & summarise

Reads forty lines and says whether they deserve your attention, and why in one sentence. Never leaves the machine.

Small or large

Fix & explain

One corrected command with a confidence and a danger flag; an explanation streamed in the panel, in your language.

Agent

Investigate

The brief handed to Claude Code, Codex, OpenCode, aider or Gemini CLI. No API key if the CLI already has one.

~/.config/kintsu/config.toml
[models.tiny]
provider = "ollama"        model = "qwen3:1.7b"     tier = "tiny"

[models.haiku]
provider = "anthropic"     model = "claude-haiku-4-5-20251001"   key = { keychain = true }

[models.claude-code]
provider = "cli_agent"     command = "claude"       tier = "agent"

[routing]
classify    = ["tiny", "rules-only"]
quick_fix   = ["tiny", "haiku"]
explain     = ["haiku"]
investigate = ["claude-code"]

[routing.constraints]
sensitive_output = "local_only"   # scene 06: a secret in the output, nothing leaves the machine
max_daily_cost   = "1.00 USD"

Anthropic · OpenAI · Gemini · Ollama · OpenRouter · Groq · Mistral · LM Studio · llama.cpp · anything OpenAI-compatible · any CLI agent

What never happens

Six things Kintsu will not do.

  • Run a command for you

    Suggestions are inserted in your line editor. You press Enter. In the panel it takes two Enters, on purpose. Destructive patterns are red first.

  • Send anything you did not see

    The Privacy tab is the exact payload. Redaction is on by default. A secret spotted anywhere forces local-only routing.

  • Make your prompt wait

    The hook costs under a millisecond on success. The quiet path never touches the network. Slow answers arrive later, as messages.

  • Replace your terminal

    Not a terminal, not a shell, not a PTY wrapper. A hook and a small resident daemon. One line in your rc file, one line to remove it.

  • Speak twice about the same thing

    The same failure twice is one bubble. Dismiss, mute, ignore per command, directory, session or forever.

  • Phone home

    No telemetry, no account, no server of ours. The only recipient of your data is the provider you configured, when you ask.

Install

One binary. One line.

Pre-alpha today: the hooks work and print a placeholder after a failure. The bubble, the daemon and the models land with v0.1. Follow the repository to know when.

build it
git clone https://github.com/nathan-poncet/kintsu.git
cd kintsu && cargo install --path .
hook your shell
# ~/.zshrc
eval "$(kintsu init zsh)"
# ~/.bashrc
eval "$(kintsu init bash)"
# ~/.config/fish/config.fish
kintsu init fish | source
later, when v0.1 lands
kintsu setup            # three questions: Ollama? a key? a CLI agent?
kintsu service install  # the daemon survives logout, restarts on crash
kintsu doctor           # what works, what is missing, what it would cost

Questions

Fair ones.

Isn't this Warp?
Warp did it first, inside Warp, with a Warp account and Warp's models. Kintsu does it in the terminal and shell you already use, with any model or agent, keys in your keychain, source on GitHub.
Isn't this thefuck?
For scene 01, yes, and Kintsu ports its best rules. thefuck waits for you to type a word, has no model for everything rules cannot know, and cannot hand a case to an agent.
Does it run my commands?
No. Never. A fix is inserted in your line; you press Enter. Read-only probes such as lsof may run when you ask Why, and the Privacy tab lists them.
Which terminals make the bubble clickable?
iTerm2, WezTerm, Kitty, Ghostty, foot, VS Code, Windows Terminal, GNOME Terminal and other VTE terminals render the links. Elsewhere the words still show and the keys still work.
Does it work over SSH, in tmux, in Herdr?
Yes. The daemon runs per user on whatever host the shell is on. tmux and Herdr are where Kintsu reads the actual output best.
Why "Kintsu"?
Kintsugi, 金継ぎ, is the Japanese craft of repairing broken pottery with gold: the crack becomes the most visible and most valued part of the piece. A failed command is a crack. Kintsu is the gold seam.
