The command failed.
Kintsu picks it up.

A small bubble under the error. It fixes the typo, explains the stack trace, or hands the whole case to the AI agent you already use. In your terminal, your shell, with your models and your keys.

The tour, in nine chapters

Scripted scenes of the designed behaviour; Kintsu is pre-alpha and real recordings replace them the day v0.1 runs. Nothing here runs a command, and nothing will in the real thing either.

One action at a time

Everything the bubble can do.

Every action has a key, a word you can click, and a command. Each card jumps to the chapter of the tour where you see it happen, and says who is doing the work: a rule, a model on your machine, a model in the cloud, or your agent.

Tab

Accept the ghost-text fix

When a rule is sure and the fix is harmless, the corrected command is already on your next prompt, dim. Tab or → accepts it; typing anything else discards it; Enter runs it.

local a rule · under a millisecond · no model

the bubble

One seam, one sentence, a line of words

Printed right under the failure, three lines at most. The words are OSC 8 links, so they are clickable in most terminals without stealing your mouse selection. It never takes a keystroke from your prompt.

local a rule, plus a tiny model that reads the output and writes the sentence

^K

Expand into the panel

The same bubble, unfolded in place under your prompt, never full screen. The command and its status, five sections with one-letter keys, mouse and wheel welcome, Esc to fold it back. Click any word of the bubble to open it there.

local Kintsu · instant

w · Why · kintsu why

Why it failed

An explanation, streamed into the panel, in your language. It reads the redacted case: command, status, output, cwd, git state, recent commands. Never your files.

cloud or local the model you routed explain to; Haiku by default, Ollama with one line of config

p · Privacy · kintsu privacy

What left the machine

The exact payload that was sent, with the redactions highlighted. Tokens, keys, passwords in URLs are redacted by default; add your own patterns. A case that contains a secret is answered locally, automatically.

local Kintsu · redaction on by default

f · Fix · kintsu fix

One command, two Enters

One corrected command, its confidence, a red flag when it is destructive. ⏎ inserts it in your line editor and closes the panel; you press Enter again to run it. Kintsu never runs anything itself.

cloud or local the model you routed quick_fix to; a rule when one knows

a · Agent · kintsu agent

Hand the case to your agent

Kintsu writes the brief, redacted, and launches Claude Code, Codex, OpenCode, aider or Gemini CLI in your terminal with it. No API key if the CLI already has one. The agent works; Kintsu steps aside.

your account the agent you configured, in your terminal

messages

Answers that arrive later

Anything slower than a prompt should wait is delivered later, above your prompt, without touching the line you are typing. In zsh and fish, immediately; in bash, at the next prompt.

local the resident daemon, one per user, started on demand

i · Ignore · kintsu mute 1h

Ignore, mute, forever

Ignore for this command, this directory, this session, or always. Mute for an hour. Editors, pagers, ssh and your own list are never triaged. The same failure twice is one bubble anyway.

local Kintsu · quiet by default

Who answers you

Four kinds of brains, one per task.

In the tour, four different things answered. Which one does what is a config file, and it degrades gracefully when a brain is missing: no Ollama means rules only for classification; no key means no cloud; no agent means Fix and Why still work.

local

Rules

Typos, wrong directory, missing flag, Docker down, non-fast-forward push. Ported from the best of thefuck. Under a millisecond, free, offline.

local

Tiny model

Reads the output, decides whether it deserves a bubble, writes the sentence, summarises forty lines into one. Ollama, a few hundred milliseconds, free.

cloud local

Small or large model

One-line fixes with a confidence; explanations streamed in your language. Anthropic, OpenAI, Gemini, OpenRouter, or any local server; your choice per task, and local only when a secret is spotted.

your account

Agent

Claude Code, Codex, OpenCode, aider, Gemini CLI, launched in your terminal with the brief. No API key if the CLI already has one.

~/.config/kintsu/config.toml
[models.tiny]
provider = "ollama"        model = "qwen3:1.7b"     tier = "tiny"

[models.haiku]
provider = "anthropic"     model = "claude-haiku-4-5-20251001"   key = { keychain = true }

[models.claude-code]
provider = "cli_agent"     command = "claude"       tier = "agent"

[routing]
classify    = ["tiny", "rules-only"]
quick_fix   = ["tiny", "haiku"]
explain     = ["haiku"]
investigate = ["claude-code"]

[routing.constraints]
sensitive_output = "local_only"   # a secret in the output: nothing leaves the machine
max_daily_cost   = "1.00 USD"

What never happens

Six things Kintsu will not do.

  • Run a command for you

    Suggestions are inserted in your line editor. You press Enter. In the panel it takes two Enters, on purpose. Destructive patterns are red first.

  • Send anything you did not see

    The Privacy tab is the exact payload. Redaction is on by default. A secret spotted anywhere forces local-only routing.

  • Make your prompt wait

    The hook costs under a millisecond on success. The quiet path never touches the network. Slow answers arrive later, as messages.

  • Replace your terminal

    Not a terminal, not a shell, not a PTY wrapper. A hook and a small resident daemon. One line in your rc file, one line to remove it.

  • Speak twice about the same thing

    The same failure twice is one bubble. Dismiss, mute, ignore per command, directory, session or forever.

  • Phone home

    No telemetry, no account, no server of ours. The only recipient of your data is the provider you configured, when you ask.

Install

One binary. One line.

Pre-alpha today: the hooks work and print a placeholder after a failure. The bubble, the daemon and the models land with v0.1. Follow the repository to know when.

build it
git clone https://github.com/nathan-poncet/kintsu.git
cd kintsu && cargo install --path .
hook your shell
# ~/.zshrc
eval "$(kintsu init zsh)"
# ~/.bashrc
eval "$(kintsu init bash)"
# ~/.config/fish/config.fish
kintsu init fish | source
later, when v0.1 lands
kintsu setup            # three questions: Ollama? a key? a CLI agent?
kintsu service install  # the daemon survives logout, restarts on crash
kintsu doctor           # what works, what is missing, what it would cost

Questions

Fair ones.

Isn't this Warp?
Warp did it first, inside Warp, with a Warp account and Warp's models. Kintsu does it in the terminal and shell you already use, with any model or agent, keys in your keychain, source on GitHub.
Isn't this thefuck?
For chapter 1, yes, and Kintsu ports its best rules. thefuck waits for you to type a word, has no model for what rules cannot know, and cannot hand a case to an agent.
Does it run my commands?
No. Never. A fix is inserted in your line; you press Enter. Read-only probes such as lsof may run when you ask Why, and the Privacy tab lists them.
Which terminals make the bubble clickable?
iTerm2, WezTerm, Kitty, Ghostty, foot, VS Code, Windows Terminal, GNOME Terminal and other VTE terminals render the links. Elsewhere the words still show and the keys still work.
Does it work over SSH, in tmux, in Herdr?
Yes. The daemon runs per user on whatever host the shell is on. tmux and Herdr are where Kintsu reads the actual output best.
Why "Kintsu"?
Kintsugi, 金継ぎ, is the Japanese craft of repairing broken pottery with gold: the crack becomes the most visible and most valued part of the piece. A failed command is a crack. Kintsu is the gold seam.
